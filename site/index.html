    Questions we expect.

    What stops the model from corrupting the books?

    The model never writes to the database. It returns JSON, and code validates it field by field. Anything unclear goes to a queue for the owner. Reminder text is built by code, and every number in a model-written briefing is checked against the ledger.

    What if it is wrong but looks valid?

    That is the real residual risk, so we show our miss rate instead of hiding it. The owner can open the raw model output for every message. Known Hindi traps are guarded in code, a known customer's record overrides a wrong direction, and the same message twice in ten minutes is held instead of applied twice.

    Why not Tally, Vyapar or a spreadsheet?

    Those need the owner to type every entry. KhataPilot starts from the messages that already exist, then handles the follow-up: who to chase, what to reorder.

    Is WhatsApp integrated?

    On purpose, not through the Business API. One-click links keep a person on every send, which is the safety design, and avoid bulk-messaging risk.

    Where does my data live?

    On your own computer, in a SQLite file. Only message text and ledger figures for the briefing go to Nebius Token Factory. There is no cloud database and no login, so it is built for one shop on one machine today.

    Why is it not instant?

    Reasoning is on, which is what makes Hinglish reliable. A message typically takes a few seconds. Messages are independent, so they can run in parallel.
